Tab 键遍历顺序

遍历规则：正整数按从小到大 → tabindex="0" 和无 tabindex

tabindex="3" 3
tabindex="1" 1
tabindex="2" 2
tabindex="0" 0
无 tabindex（自然顺序）自然

💡 按 Tab 键测试：顺序是 1 → 2 → 3 → 0 → 自然

正整数 tabindex（❌ 不推荐）

正整数会打乱自然的 DOM 顺序，维护困难。

第三个元素 tabindex="3"
第一个元素 tabindex="1"
第二个元素 tabindex="2"

⚠️ 问题：HTML 中的顺序是 3→1→2，但 Tab 键顺序是 1→2→3，容易混乱

为什么避免正整数？

  • 维护困难：新元素该用哪个数字？
  • 顺序不直观：需要记住所有元素的 tabindex 值
  • DOM 顺序更灵活：依靠文档结构决定顺序

tabindex="0" — 自然顺序聚焦

tabindex="0" 让元素参与自然的 Tab 顺序（与 DOM 顺序一致）。

第一个 div 0
第二个 div 0
第三个 div 0

✅ 按 DOM 顺序遍历，与普通按钮/链接一致

使用场景

  • 将 div/section 变为可聚焦，配合 onClick/onKeyDown 使用
  • 自定义卡片组件需要键盘导航时
  • 需要用键盘访问的可视化组件

tabindex="-1" — 仅 JS 聚焦

tabindex="-1" 元素不能通过 Tab 键聚焦，但可以用 JavaScript 的 focus() 方法聚焦。

tabindex="-1" - 可用 JS 聚焦 -1
无 tabindex - 普通 div 不可聚焦

使用场景

  • 实现"跳转到主要内容"的链接（视觉隐藏，JS 控制聚焦）
  • 自定义下拉菜单的选项（用方向键导航，tabindex="-1" 选项）
  • 模态框中的关闭按钮（打开时聚焦，Tab 不遍历）

代码规范检查清单

  • ✅ 优先使用原生元素（button, a, input）
  • ✅ 自定义组件使用 tabindex="0"
  • ✅ 需要程序聚焦时使用 tabindex="-1"
  • ❌ 不要使用 tabindex > 0
  • ❌ 不要对可聚焦元素（button, a）添加 tabindex
