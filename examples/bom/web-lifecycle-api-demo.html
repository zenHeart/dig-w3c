页面生命周期状态机

Web Lifecycle API 将页面生命周期划分为 5 个互斥状态，每个状态之间有明确的转换条件。

🔍 状态详解
状态 说明 触发条件
Active 页面在前台，完全可交互 页面首次加载、用户切回页面
Passive 刚离开前台，尚未完全隐藏 切换标签但当前标签仍可见
Hidden 完全不可见，但未被冻结 切换标签、最小化窗口、切换应用
Frozen JS 执行暂停，计时器冻结 浏览器自动将后台页面冻结
Terminated 页面销毁，内存释放 关闭标签、导航离开、内存回收
⚡ 与传统事件的关系

传统事件 beforeunload / unload 不可靠，而 Lifecycle API 提供的事件行为更一致：

事件推荐度说明
visibilitychange推荐最可靠的可见性检测，iOS Safari 支持
pagehide推荐比 unload 可靠，persisted 判断 bfcache
pageshow推荐包括 bfcache 恢复场景
freeze / resume实验性Chrome 支持，其他浏览器有限
beforeunload谨慎可弹窗提示，但不可靠
unload不推荐iOS Safari 等场景下不触发

核心事件详解

Lifecycle API 的 5 个核心事件，每个事件对应状态流转中的关键节点。

visibilitychange 标准 0
document.visibilityState 从 visible 变为 hidden 或反之

最可靠的可视性检测方式。文档可见性发生变化时立即触发，iOS Safari 良好支持。

document.addEventListener('visibilitychange', function() {
  if (document.visibilityState === 'visible') {
    console.log('页面可见');
  } else {
    console.log('页面不可见');
  }
});
pageshow 标准 0
页面显示时触发，包括首次加载和 bfcache 恢复

页面首次加载和每次显示时触发。event.persisted = true 表示从 bfcache 恢复。

window.addEventListener('pageshow', function(event) {
  if (event.persisted) {
    console.log('从 bfcache 恢复');
  } else {
    console.log('首次加载');
  }
});
pagehide 标准 0
页面隐藏时触发，判断是否进入 bfcache

页面从任意状态变为 hidden 时触发。event.persisted = true 表示页面可恢复（bfcache），false 表示将卸载。

window.addEventListener('pagehide', function(event) {
  if (event.persisted) {
    console.log('进入 bfcache，可恢复');
  } else {
    console.log('即将卸载');
  }
});
freeze 待定 0
页面被冻结，JS 执行暂停

浏览器冻结页面时触发。冻结后无法执行任何 JavaScript 代码，必须提前完成所有清理工作。

document.addEventListener('freeze', function() {
  // 冻结后无法执行异步操作
  // 必须提前在 pagehide / visibilitychange 中保存状态
  console.log('页面已被冻结');
});
resume 待定 0
页面从冻结状态恢复

页面从冻结状态恢复时触发。可在此恢复资源、重新初始化组件。

document.addEventListener('resume', function() {
  console.log('页面从冻结状态恢复');
  restoreResources();
});

后退缓存（bfcache）机制

bfcache（Back-Forward Cache）是浏览器的特殊缓存，保存整个页面快照，使"后退"操作瞬间恢复。

♻️

注意：页面 A 的 JavaScript 堆、DOM 状态、表单数据、滚动位置全部保留，无需重新加载。

📊 pagehide persisted 属性

通过 event.persisted 属性判断页面状态：

persisted含义后续状态开发者应对
true 页面进入 bfcache Frozen → 可恢复 暂停资源占用，页面会自动恢复
false 页面即将卸载 Terminated 保存所有关键状态到持久化存储
⚠️ 哪些情况会阻止 bfcache？
  • 页面持有未完成的 XMLHttpRequest 或 fetch 请求
  • 打开了 IndexedDB 读写事务
  • 存在打开的 WebSocket 连接
  • 包含带有 beforeunload 监听器的 iframe（部分浏览器）
  • 页面通过非正常方式被卸载（如浏览器崩溃）
✅ 正确支持 bfcache 的代码模式
// 页面隐藏时的处理
window.addEventListener('pagehide', function(event) {
  if (event.persisted) {
    // 进入 bfcache，释放非必要资源
    pauseAnimation();
    releaseMediaStream();
  } else {
    // 即将卸载，保存关键状态
    localStorage.setItem('app_state', JSON.stringify(getState()));
  }
});

// 页面从 bfcache 恢复
window.addEventListener('pageshow', function(event) {
  if (event.persisted) {
    // 从缓存恢复，重新初始化
    restoreState();
    resumeAnimation();
  }
});
